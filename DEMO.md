# Capture Test — judge walkthrough

The [phone-format walkthrough](public/demo.mp4) records the actual local dashboard and one public NEAR transaction page. Its dashboard reads the committed mainnet snapshot; changing model inputs performs a browser calculation, while the displayed offline rebuild output was generated by `npm run rebuild`. No live network request is implied during the dashboard segment.

## One action-to-result route

1. In the first screen, read the verdict and **72/80** concentration result. Select **Explore the evidence**. The latest historical tab shows **170 signer-touching transactions** but only **80 direct `v1.signer.sign` receipts**.
2. Open a row under **Inspect a direct request**. Read the exact receipt ID, caller, method, timestamp, and parent hash, then open its public transaction on Pikespeak. The [receipt CSV](public/data/receipt-audit.csv) lets a judge check all rows.
3. Inspect the twelve spaced same-day windows: the pooled top three initiated **1,219/1,482 (82.3%)** direct requests. This samples roughly 9% of the first-to-last block-height span, **not every request that day**. The three post hoc offset checks are in [METHODOLOGY.md](METHODOLOGY.md).
4. Look at the 80 receipt outcomes: **0.033515283 NEAR** in `tokens_burnt`, or **0.000418941041 NEAR per direct request**. The contemporaneous 5–12 November epoch audit measured **645,868.122 NEAR** in gross rewards, about **92,266.875 NEAR/day**. This measures only the `sign` stage; it excludes other workflow fees and is separate from Intents buybacks.
5. Change assumed requests/day to **1,000,000** and independent-app share to **100%**. The result is **418.94 NEAR/day**, only **0.4541%** of the observed daily gross issuance baseline. The independent share is an assumption, not an inferred operator count. The panel shows that roughly **2.2 million direct requests/day** would be needed for a 1% offset at the sampled charge.
6. Read the verdict: use is real, broad independent demand is unproven, and measured sign-stage burn is not yet materially large against issuance. Scroll to the offline command and its matching generated output.

## Reproduce

```sh
npm test
npm run rebuild
npm run serve
```

`npm run rebuild` recalculates the dashboard data, CSVs, and THESIS.md offline from committed receipts and epoch rewards. `npm run concentration-check` independently recounts the receipt CSV; `npm run issuance-check` re-queries archival NEAR RPC; `npm run refresh` separately refreshes live FastNear, DeFiLlama, and cross-chain sources. Public API limits can delay live checks. No credential is required.
