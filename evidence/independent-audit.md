## Corrections and boundaries

1. **Timestamp semantics:** The legacy extractor stores `entry.receipt.block_timestamp`, which is the timestamp recorded on the receipt, not `entry.execution_outcome.block_timestamp`. They can differ. For completion receipt `FvAvk6W1dmLLT5BcH8MmfVwSEdmX8rdE3G1c3pcfVp3Q`, fresh trace creation/recorded time is `1794362332581785009`, while execution time is `1794362336251602747`. Existing statements calling every CSV timestamp an execution time are unsupported. Two archived receipt-record timestamps lie just outside the UTC day, including one `sign`; the normalized archive alone cannot prove exact execution-time spillover counts. Relabel the timestamp and retain parent-cohort selection, or fetch execution timestamps separately. The 80 checked direct request receipts have matching recorded/execution timestamps, but this does not establish equality for all 17,665.
2. **Activity purpose:** A signature request can authorize an arbitrary payload, including authentication. The fresh `fast-auth.near` trace in parent `H3LWSUYvC2mHcXMbeUKbhoePHpEVA2q3cLg7fLuyuwiR` contains a JWT-related derivation path. Signing requests are not synonymous with destination-chain transfers, payment volume or even necessarily transfer intent. Signature scheme alone does not identify a destination chain.
3. **Stale thesis text:** The old generated thesis describes a default independent-app share of 25%; the shipped UI uses 100%. Neither number is an observed adoption estimate. The text also calls twelve ranges “additional,” though one overlaps the latest historical window; there are eleven additions.
4. **Temporal comparability:** Short equal-block historical windows support a comparison of those observed cohorts, not a network adoption trend. Wall-clock durations and time-of-day differ. A full November 11 day must not be compared directly to an earlier 1,000-block sample as if their request totals measured growth.
5. **Independent reproduction boundary:** This is independent calculation and a fresh requery of the same public providers, not independently operated full-node validation. The full-day archive stores normalized, receiver-filtered records without raw `receiver_id` or complete transaction traces. The recount cannot prove the extraction omitted nothing, the index was exhaustive, or every retained full-day receiver was correct. All 80 live fee receipts passed the receiver check; that is a bounded sample.
6. **Economic and adoption boundaries:** Contract accounts can aggregate users, multiple accounts can share an operator, and activity can be automated. Account concentration neither proves artificial demand nor counts independent applications. Direct gas burn excludes parent transactions, responses, completion, other contracts and external-chain costs; it is neither protocol business revenue nor a valuation model. Arbitrary thesis hurdle thresholds should be labeled research decision rules, not statistically validated investment triggers.

## Reproduce

`python3 scripts/independent-audit.py` independently checks the committed cohort, CSV, selected windows, fee IDs, fee sum, reward sums, supply subtraction and context series. `python3 scripts/independent-audit.py --live` additionally rechecks 80 fee receipts, 25 reward maps, four day-boundary blocks, four supply-boundary blocks and three protocol configurations. The latter writes a dated result and depends on public endpoint availability. Neither command recollects the full-day population or changes the main snapshot.

The [NEAR Chain Signatures documentation](https://docs.near.org/chain-abstraction/chain-signatures) corroborates the account-derived MPC signing mechanism and the distinction between requesting a signature and submitting a signed transaction to an external chain. The [nearcore economics specification](https://github.com/near/nearcore/blob/master/docs/Economics/Economics.md) explains rewards but contains general contract-reward text that does not supersede the dated live protocol configuration.

## Production follow-through · 14 November 2026

The timestamp wording and stale model documentation above have been corrected. The current model takes daily direct requests and a fee multiple; it does not infer application independence. Rebuild now verifies two sealed compressed archives, regenerates the comparison from raw traces, and rejects a missing emitted receipt. All 25 tests pass. A separate independent Python implementation now recounts both historical hours, their complete index/hydration hash sets, receipt graph closure, exact request IDs, caller counts and fee sums. See `independent-offline.json`. Offline audits preserve dated live rechecks in `independent-verification.json`.

A fresh read-only live audit on 14 November 2026 reverified 80 direct-stage fee receipts, 25 reward maps, four UTC boundaries, four supply boundaries and three protocol configurations. It queried the same providers and is not independent full-node validation. No transaction was signed or broadcast.
